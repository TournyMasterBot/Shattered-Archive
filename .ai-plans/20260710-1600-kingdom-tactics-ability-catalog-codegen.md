# Plan: Kingdom Tactics — DSL ability catalog codegen (spells/songs/skills)

Created: 2026-07-10T16:00:00-05:00 · Workspace: /workspace/shattered-archive · Status: COMPLETE
Task: Distill the DSL ability catalog (spells/songs/skills + their class ability groups) into checked-in generated TS the engine can reference, following the existing `pnpm codegen` pattern.

## Goal
The engine gains a generated `src/data/dsl/abilities.ts` (a checked-in catalog of every
DSL ability — key/name/type — plus every class ability group with its transitively-resolved
member keys), produced by extending the existing `pnpm codegen` script and exposed through
the data barrel with lookups + integrity tests. **Catalog only** — no combat/mechanics
wiring, no stat scaling, no saves this pass (those are a later balance-authoring plan).
Done when: `pnpm codegen` regenerates `abilities.ts` deterministically, the engine builds,
and catalog-integrity tests pass (counts match DSL; no group member key is dangling).

## Constraints
- Follow the EXISTING distillation pattern: generated file is **checked in** (not git-ignored),
  regenerated by an explicit `pnpm codegen` step, NEVER read from the .cs at runtime. Do NOT
  add codegen to `pnpm build`.
- DSL ability files are name + lore ONLY — no damage/scaling/saves/magnitudes. Emit structural
  facts (key, name, type, group membership); author NO balance numbers here.
- Ability `type` comes from the source folder / base class default: Spells→'spell', Songs→'song',
  Skills→'skill'. `name` from the `Name = "..."` constructor assignment; `key` = C# class name.
- Group membership = direct `new X()` / `X.Instance` refs PLUS transitive `GetAbilitiesByType<G>()`
  group references, resolved recursively with a cycle guard, filtered to known ability/group keys.
- Isomorphic engine rules unchanged; generator is a dev-time Node script (already excluded from
  the shipped tsconfig, like the sibling generators).
- pnpm only; host runs the JS build/tests (never qwen in-container).
