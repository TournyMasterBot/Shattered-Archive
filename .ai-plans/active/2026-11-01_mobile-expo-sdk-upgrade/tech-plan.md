## Goal
The mobile app builds, installs and runs on the latest stable Expo SDK (SDK 58: `expo` 58.x, `react-native` 0.88.x, `react` 19.3) on Android, with these provable results:
1. `tsc --noEmit`, `expo lint` (0 errors) and the full Jest suite pass, with no suite failing to run (baseline 51 suites / 699 tests).
2. `@supersami/rn-foreground-service` is gone; the Android background connection runs on `react-native-background-actions` behind the same four functions in `features/connection/connection-service.ts`.
3. Every hand edit in the committed `android/` project is produced by a config plugin and `android/` was regenerated with `expo prebuild`.
4. A cold start shows no Firebase deprecation warning from our code, no `NativeEventEmitter` warning and no `ReferenceError`.
5. An SDK 52 install upgraded in place to the SDK 58 build keeps its stored data and its login.

## Out of scope
- Building or verifying iOS (decision 2026-11-01); only its configuration is regenerated and reviewed (Phase 7). `Podfile.lock` is regenerated by the owner on the Mac build server.
- Stepping through intermediate SDKs; stopping at SDK 56 (decision).
- Play Store submission, release signing changes, store listing.
- New app features; replacing libraries other than the foreground service (`react-native-render-html` stays unless found broken; then a new item).
- The web repo and the C# server.
- The `NativeEventEmitter` warning's other possible sources: only the foreground-service source is addressed.

## Standards applied
- **TypeScript** (`docs/standards/typescript.md`): explicit types, `unknown` narrowing, no new `any` in production code; storage and service code fails safe with `try`/`catch` and a single fixed-message `console.warn` that carries no values; tests are `__tests__/*-test.ts(x)` and assert concrete behaviour, every added branch and error path. Mobile modules are kebab-case in `features/<area>/`.
- **JavaScript** (`docs/standards/javascript.md`): CommonJS; config plugins are `plugins/with<Name>.js`, idempotent, with a Jest test in `plugins/__tests__/with<Name>-test.js` plus a scratch `expo prebuild` check; lint is `expo lint` with `.eslintrc.js`.
- Gradle (Groovy), XML, Ruby (Podfile), YAML and Markdown are not language standards here; they follow `CLAUDE.md` of the mobile repo and the repo-wide rules. No Kotlin is written (decision: library, not an own module), so no Kotlin standard is needed.
- Not decided and not needed: async-and-state and security-sensitive-code categories (no new state or input handling is written; the foreground-service module is a thin adapter).
