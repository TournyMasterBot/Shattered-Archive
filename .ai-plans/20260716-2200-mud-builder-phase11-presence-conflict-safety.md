# Plan: MUD Builder — Phase 11 (builder presence + save-conflict safety)

Created: 2026-07-16T22:00:00Z · Workspace: /workspace/shattered-archive · Status: COMPLETE
Task: Make multi-builder editing safe: saves detect that the on-disk file changed since it was loaded (409 instead of silent last-write-wins), builders can see who else is working in an area, and "assumed to live in another area" reference warnings become a REAL cross-area guard — resolved against every listed area, with navigable links to the defining entity, so only genuinely missing vnums warn.

## Goal
Two builders with API keys can work at the same time without silently clobbering each other. Every area load carries a content hash; a save whose base hash no longer matches the disk gets a 409 with a clear "someone else saved" story and a UI path to reload/re-apply. The area list shows advisory presence badges ("Kess is editing midgaard.are"). Cross-area vnum references are checked against the actual world index instead of assumed: refs that resolve show as clickable "defined in <file>: <name>" links (preview pane, import report, world dashboard), and only vnums missing from EVERY listed area remain warnings. Done when the E2E proves the conflict 409 and the resolver end-to-end through the edge, presence appears/expires live, all suites stay green, and the MUD never restarts.

## Constraints
- STABILITY IS KING; no C changes. This is builder-server/-client only.
- Conflict detection is on AREA saves (PUT /api/areas/:file) first; skills/groups overlays are single-file globals and can follow the same pattern in a later phase if wanted.
- Backward compatible: a PUT WITHOUT baseHash keeps today's behavior (the builder UI always sends it; raw API users opt in). Never break the existing suites.
- Presence is ADVISORY only — an in-memory heartbeat registry, never a hard lock (a crashed browser must never wedge an area; entries expire ~60s without a heartbeat). No disk writes, no audit lines for presence.
- Presence names come from the acting credential (key label or "master"), never free-form client input alone; reads stay open but presence POST is a mutation-shaped request and thus goes through the Phase 9 guard when auth is on.
- All code testable in isolation; never-crash server contract; qwen (container) must NOT run pnpm install|build|test.
