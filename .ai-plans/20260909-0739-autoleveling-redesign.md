## Goal
The auto-leveling feature is a linear wizard (Area → Targets → Combat → Review → Start). Area definitions (route, level range, start room, notes) and recommended targets are served by the C# service (`GET /maps/autoleveling/areas`), proxied by web-server (cache + offline fallback), and cached client-side in IndexedDB — the same read-through pattern as maps/beasts. **Every DSL class and each class's Active skills/spells/songs (with the level they're learned at) are served the same way** (`GET /maps/autoleveling/classes`), so the Combat step offers the player's class's real buffs and combat abilities to pick from — not just free text. Buff checklists and per-class fight commands are configured in the wizard's Combat step and, together with any user-added targets / custom paths, persist to a local IndexedDB user-data store that syncs to the account profile when logged in. The engine executes every triplet the UI exposes (no dead config); pre-round buffs fire, tick-refresh buffs re-fire, and critical buffs react mid-combat. Done when: a logged-out user picks "Centaur Village", accepts defaults, adds one cooldown command, and starts a working run without a script textarea; the class picker lists every class and its abilities; the old 3-tab modal is gone; and nothing area- or class-specific is compiled into the client bundle.

#### 7.1 `BuffRow` target shape (`autoleveling-user-data.ts`)
```ts
export interface BuffRow {
  label: string;
  cmd: string;                 // out-of-combat (re)cast
  affect?: string;             // gate: skip while this GMCP affect is active (if_affect_missing)
  refreshTicks?: number;       // gate: recast every N game ticks since last cast (send_every_ticks)
  //  (affect XOR refreshTicks; neither set = cast every round)
  inCombatCmd?: string;        // if the affect drops WHILE is_fighting: fire this instead (item action:
                               //   quaff <potion> / brandish <staff> / zap <wand>). Needs item in inv.
                               //   Not set → buff waits for combat to end (NO mid-fight spell recast).
  holdNearLevel?: boolean;     // stop refreshing (let it fall) when tnl <= est. next-kill XP. For haste.
}
```
Storage is forward-compatible (rows live in a record's `data` array) — no migration needed; just widen the type. `FightRow` unchanged.
