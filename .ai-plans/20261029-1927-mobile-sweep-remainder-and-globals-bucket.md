### Leading hypothesis (UNVERIFIED — step 1 must confirm) for BOTH web reports
- `/workspace/shattered-archive/apps/game-client/src/pages/MainContainer.tsx` l.190-197 derives `connectionId`: `'default'` when `gameConn.currentHost/currentPort` are empty (not connected / not yet connected), `'dsl-mud'` when the host contains `dsl-mud`, otherwise `host:port`.
- Global scripts are stored per connection: `features/userScripts/globalScriptsStore.ts` key `shatteredArchive.userGlobalScripts.<connectionId>`; `UserScriptSandboxModal.tsx` (l.606 `useGlobalScripts(connectionId)`, l.748-751 draft synced from `globalMgr.sources`) and `hooks/useGlobalScripts.ts` read/write the bucket for the CURRENT connectionId only.
- So a script saved while the id is `default` (sandbox opened before/while disconnected, or during a reconnect gap) is invisible when the modal is reopened under `dsl-mud`, and vice versa → "blank on reopen".
- Cloud sync uploads every bucket (`getAllGlobalScriptBuckets`, l.216) with its connectionId and `replaceGlobalScriptBuckets` (l.243) writes each bucket back under the same id (`hooks/useAccountModal.ts` ~l.91, ~l.162-213, then `window.location.reload()`). A laptop save made under `default` therefore loads on desktop into `default`, while the connected desktop reads `dsl-mud` → "farm scripts never show up on desktop". Same mismatch family that was fixed on mobile (mobile uses `DEFAULT_BUCKET_ID='dsl-mud'`, legacy `'default'` fallback in `features/scripts/global-scripts-storage.ts`).
- Counter-signals to check: the screenshot shows the editor WITH content, so also rule out the draft-reset effect (`globalMgr.sources` identity change resetting `globalDraft`), `useGlobalScripts` initial state vs. connectionId change, and `console.log` noise in `getGlobalVarsSnapshot` (l.298, remove if confirmed pure debug).
