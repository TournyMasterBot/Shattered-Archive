# AI rules — ShatteredArchive

Loaded into the local qwen agent (`pnpm run qwen`) so it follows the repo's rules. Short on purpose: only rules that cannot be inferred from the code.
Authoritative sources: `CLAUDE.md` and `.github/copilot-instructions.md` (this file must not contradict them). Keep this file under 45 lines.
Rule IDs are reported by the mechanical gates (Shattered-AI `tools/gates`), so keep them stable.

## Packages
- PKG-1 pnpm via Corepack only: never npm or yarn. The pinned version is `packageManager` in package.json; never suggest upgrading pnpm without updating its sha512.
- PKG-2 Installs in scripts, docs and Dockerfiles use `pnpm install --frozen-lockfile`.
- PKG-3 Never `--ignore-scripts` globally. A native build dependency is allowlisted in BOTH `onlyBuiltDependencies` and `allowBuilds` in pnpm-workspace.yaml, only with a justification.

## Dependencies
- DEP-1 Keep `minimumReleaseAge: 1440` (minutes) in pnpm-workspace.yaml; never remove or lower it. pnpm 11 ignores pnpm settings in .npmrc; `pnpm config get <name>` returning `undefined` means a setting is not read.
- DEP-2 Registry packages only: no `file:` outside the workspace, no `git:`/`github:`/`bitbucket:`, no https tarballs, no `link:` outside node_modules. `workspace:*` is fine.
- DEP-3 `shamefully-hoist=false`: each package declares its own imports; fix package.json instead of hoisting.
- DEP-4 No new dependency unless necessary, and justify it.

## Docker
- DKR-1 Every `FROM` is `image:tag@sha256:<digest>` with a `# <version>` comment above it when the tag does not encode the version. Build and runtime stages use the same digest for the same image. Never `:latest`, `:alpine` or a bare major tag. Third-party `image:` lines in compose files follow the same rule.
- DKR-2 Node stages set `ENV COREPACK_ENABLE_STRICT=1` before `RUN corepack enable`.
- DKR-3 Alpine stages run `RUN apk --no-cache upgrade` as the first RUN after FROM.
- DKR-4 Changing a digest means changing EVERY FROM that uses the image, the version comment, and the "Known open CVEs" table in CLAUDE.md.

## Code and tests
- COD-1 TypeScript first, explicit types, no `any` without a reason. Follow the existing pattern of the folder you touch; small diffs; no drive-by reformatting.
- COD-2 A change to script logic ships with tests of concrete, observable behavior that cover every code path you added (branches and error paths). Never assert on log output unless the code under test is a logger; no placeholder, skipped, tautological or snapshot-only tests. Docs, data and config (md, txt, json, css) need no tests. If code cannot be tested meaningfully as written, do NOT refactor it on your own: describe the smallest injectable seam and ask the user.

## Security, privacy, licensing
- SEC-1 No telemetry, tracking or hidden network calls. Never log secrets, tokens or personal data. Security changes follow SECURITY.md.
- LIC-1 Say "ShatteredArchive Software". No third-party copyrighted game content or raw server files. Keep docs aligned with DISCLAIMER.md, PRIVACY.md and LICENSING.md.

## Git
- GIT-1 Pull requests target `release/dev`; never suggest direct pushes to protected branches. The agent never commits (the user does).

## Generated indexes
- IDX-1 An index entry (`.annotated`, `.ai-context`) records only context the code cannot tell: a constraint, a relation to a sibling, why-not, a gotcha, an edit-together pair, where the tests are. Never restate the file or folder name, never replace a context-bearing entry with something thinner (only add to it), and writing nothing is fine. Decisions from a session go in the folder's existing index files.

## Maintenance
- MNT-1 Low priority, ongoing: periodically check for newer versions of pinned images, packages and tools that are MORE THAN 24 HOURS old (`node ../Shattered-AI/scripts/update-check.mjs`). Report only; apply updates as a reviewed change. Never adopt a version younger than 24 hours.
